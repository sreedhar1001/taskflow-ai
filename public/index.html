🏗️ Architecture Overview

TaskFlow AI is a full-stack web app. Every component shown below is real and running live.

🌐

Frontend

Vanilla HTML/CSS/JS. Listens to a live Server-Sent Events stream and updates the diagram + step cards in real time.

⚙️

Express API

Node.js server that receives tasks, orchestrates Gemini calls, persists results, and broadcasts SSE events.

🗄️

SQLite DB

Lightweight embedded database. Stores every run and step — including outputs, durations, and retry counts.

🤖

Gemini AI

Powers step decomposition and step execution. Uses gemini-3.8-flash via the official google-genai SDK.

🛡️ Failure Recovery

The app is designed to handle AI failures gracefully at three levels:

🔁

Exponential Backoff Retry

Each step retries up to 3 times: after 1s, 2s, and 4s. The step shows "Retrying" live during each attempt.

⚡

Circuit Breaker

After 3 consecutive failures the circuit opens, blocking AI calls for 30s to avoid flooding a failing API.

💾

Partial Progress

Completed steps are saved to SQLite. Retry only re-runs the failed steps — completed work is never lost.

🔌 Live SSE Protocol

The diagram updates are powered by Server-Sent Events. Here's the event stream your browser receives:

// 1. Connection to /api/runs/:id/stream // Server sends a snapshot of current state immediately event: snapshot data: { run: {...}, steps: [...] } // 2. Steps are defined after goal parsing event: steps_defined data: { steps: [{ name, description, status }, ...] } // 3. Each step fires updates as it progresses event: step_update data: { id, index, status: "running" | "retrying" | "completed" | "failed", output?, error?, durationMs? } // 4. Run finishes event: run_update data: { status: "completed" | "failed" }

🗃️ Database Schema

-- Every submission is a run CREATE TABLE runs ( id TEXT PRIMARY KEY, goal TEXT, status TEXT, -- queued | running | completed | failed created_at TEXT, finished_at TEXT ); -- Each AI step inside a run CREATE TABLE steps ( id TEXT PRIMARY KEY, run_id TEXT REFERENCES runs(id), index_num INTEGER, name TEXT, description TEXT, status TEXT, -- queued | running | retrying | completed | failed attempts INTEGER, output TEXT, error TEXT, started_at TEXT, finished_at TEXT, duration_ms INTEGER );
